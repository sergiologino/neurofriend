# Архитектурные решения

Формат: **ID | дата | статус | решение | контекст**

---

**D-001 | 2026-04-12 | Accepted**

- **Решение:** Monorepo в `Application/` с подпроектами `backend/` (FastAPI) и клиентом на **Flutter** (iOS, Android, **Web** из той же кодовой базы, опционально desktop позже).
- **Контекст:** SRS (Implementation v4.1, Build Plan v4.2) рекомендует monorepo на старте и Flutter для mobile-first; пользователь явно запросил веб + мобильные версии — Flutter web снижает дублирование по сравнению с отдельным стеком только для веба.
- **Альтернативы:** отдельный frontend для web (React/Next) + Flutter mobile — отклонено из-за двойной поддержки UI/контрактов на MVP; нативные Swift/Kotlin — отклонено из-за стоимости сопровождения трёх кодовых баз.

**D-002 | 2026-04-12 | Accepted**

- **Решение:** Backend — **модульный монолит** FastAPI, не набор микросервисов на MVP.
- **Контекст:** SRS прямо указывает старт с одного runtime и чётких доменных модулей.

**D-003 | 2026-04-12 | Accepted**

- **Решение:** Единственный источник истины для **разработки кода** в этом репозитории — файлы в `docs/ai/`; SRS на диске остаётся нормативом продуктовых требований, синхронизируемым через эти документы при изменениях.

**D-004 | 2026-04-12 | Accepted**

- **Решение:** Первый продакшн-поток **голоса** — **OpenAI Whisper** (STT) и **OpenAI TTS**; доступ к смене провайдера через внутренние абстракции (`SpeechToText` / `TextToSpeech` или эквивалент), без привязки доменной логики к конкретному API.
- **Контекст:** Нужен голос «сразу»; позже — более подходящий движок/модель без переписывания сценариев.

**D-005 | 2026-04-12 | Accepted**

- **Решение:** **Чат не является источником истины** для нейродруга; он **дублирует** голосовой обмен (и служит fallback при недоступности голоса). **Активный тред:** при **500 сообщениях** (входящие+исходящие) — тред **архивируется**, создаётся новый активный; в новый переносятся **10 последних** сообщений старого треда; архивы читаемы отдельно.
- **Контекст:** Требование пользователя к UX и отладке; доменная истина остаётся в событиях/памяти/состоянии.

**D-006 | 2026-04-12 | Accepted**

- **Решение:** Отдельный **UI отладки/прозрачности**: история **действий нейродруга** и **взаимоотношений** (события, сдвиги state, инициатива, память) для совершенствования поведения — не смешивать с обычным чатом как единственным экраном.
- **Контекст:** Запрос на инструменты наблюдения за системой.

**D-007 | 2026-04-12 | Accepted**

- **Решение:** Первая схема БД и миграция создаются через `Base.metadata.create_all(bind=)` внутри Alembic revision `20260412_0001` (одноразово для старта); дальнейшие изменения — отдельными ревизиями с явными операциями.
- **Контекст:** Ускорить bootstrap без ручного DDL; при росте схемы предпочтительны автогенерация или явные `op.add_column` и т.д.

**D-008 | 2026-04-12 | Accepted**

- **Решение:** Для разработки **основной** вариант — **локальный PostgreSQL на машине разработчика**; контейнер Postgres в `docker-compose` не обязателен и остаётся для окружений без локального инстанса или полного стека в Docker.
- **Контекст:** У разработчика уже есть постоянно используемый локальный Postgres; дублировать БД в Docker не требуется.

**D-009 | 2026-04-13 | Accepted**

- **Решение:** Полная модель личности по SRS (слои identity/state/memory/…) не сводится к одному промпту; на MVP **усиливаем поведение через пресеты** (`gender_style`, `life_legend`, `character_prompt`) и **общие инструкции естественности диалога** в LLM, без ожидания, что модель уже ведёт себя как финальный продукт. Дальше — семантическая память (Qdrant), инициатива, углубление доменной модели.
- **Контекст:** SRS требует друга как личность (не только вопросы по теме); пользователь согласен, что на раннем этапе это поэтапно.

**D-010 | 2026-04-13 | Accepted**

- **Решение:** Первая версия **семантической памяти** — **Qdrant** + эмбеддинги **OpenAI** (тот же ключ, что для чата); источник истины по фактам диалога по-прежнему **PostgreSQL (события/сообщения)**; векторы — для **поиска релевантных фрагментов** в промпт. Дублирование чанков в Postgres и фоновая консолидация — следующими шагами (`memory_consolidation` — заготовка).
- **Контекст:** Этап 6 ROADMAP; без Qdrant или ключа OpenAI цепочка деградирует (пустой retrieval).
