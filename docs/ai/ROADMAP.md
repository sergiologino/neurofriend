# План реализации по этапам

Истина для поведения нейродруга: **события, память, состояние, отношения** (PostgreSQL + Qdrant + доменная логика). **Чат** — только зеркало/дубликат голосового потока и запасной канал, если голос недоступен.

## Принципы потока

1. **Голос в приоритете:** пользователь говорит → распознавание (**OpenAI Whisper**) → тот же пайплайн, что и для текста → ответ модели → озвучивание (**OpenAI TTS**) → параллельно запись **транскрипта/реплик в чат** (как дубликат).
2. **Текст в чате** (ручной ввод) — опциональный fallback; обрабатывается тем же use-case «сообщение пользователя», без отдельной «истины».
3. **Смена голосового стека** (Whisper/TTS → другой провайдер) — за границами абстракций `SpeechInput` / `SpeechOutput`; этапы ниже закладывают интерфейсы под замену реализации.

---

## Этап 1 — Каркас и инфраструктура

- Monorepo: `backend/`, Flutter-приложение, `infra/docker-compose` (Postgres, Redis, Qdrant; при необходимости minio для аудио).
- FastAPI: конфиг, health, CORS, async DB, клиенты Redis/Qdrant.
- Модели данных (минимум): User, NeuroFriendProfile, IdentityCore, EventLog, MemoryItem (черновик), ConversationThread, Message — с явным разделением **событий диалога** и **записей чата-транскрипта**.
- Миграции Alembic.
- Автотесты: health, миграции smoke.

**Выход:** поднимается стек, пустой но расширяемый backend.

---

## Этап 2 — Голосовой контур (MVP): Whisper + LLM + TTS

- **Вход:** загрузка аудио (Flutter: запись → multipart или поток по решению платформы) → `POST` perception/voice endpoint.
- **Whisper:** транскрипт; сохранение сырого аудио опционально (политика хранения/удаления).
- **Пайплайн ответа:** тот же orchestrator, что для текста: identity, state, relationship, memory retrieval, gap — по SRS.
- **TTS:** генерация аудио ответа; возврат клиенту URL/bytes + метаданные (длительность, модель).
- Логирование **диалоговых событий** в EventLog (типы: `voice_message_in`, `voice_message_out`, при необходимости зеркальные `text_message_*` для транскриптов).
- Обновление affect/bond/memory по существующим правилам (lite на первом шаге).

**Выход:** end-to-end «сказал — услышал ответ голосом»; истина в событиях/памяти, не в UI.

---

## Этап 3 — Дублирование в чате и политика тредов

- UI: лента сообщений показывает **те же реплики**, что голос (транскрипт пользователя + текст ответа или подпись к TTS).
- Связь сообщения чата с **id события** (`event_id` / `utterance_id`), чтобы не плодить вторую модель смысла.
- **Лимит 500 сообщений** на активный тред (подсчёт: суммарно user+assistant в активном `ConversationThread`).
- При достижении лимита: текущий тред → **archived**, создаётся новый **active**; в новый тред **копируются 10 последних сообщений** предыдущего (как транскрипт-якорь continuity); полная история старого треда остаётся в архиве и доступна для чтения.
- Ручной ввод в чате при отключённом микрофоне — тот же backend-пайплайн, помечать источник (`text_fallback` vs `voice`).

**Выход:** чат как зеркало + архивы; автотесты на лимит, архивацию, carryover 10.

---

## Этап 4 — UI отладки: отношения и действия нейродруга

- Экран(ы) **«Инспектор»** (можно за флагом `debug` или отдельная секция настроек разработчика):
  - временная лента **событий** (инициатива, сдвиг state, промоция памяти, gap, ключевые решения политики);
  - карточка **отношений** (текущие метрики + краткая динамика, без сырого спама чисел);
  - ссылки на связанные **event id** для корреляции с чатом.
- Read-only API: `GET .../events/timeline`, `GET .../relationships/...`, при необходимости `GET .../state/history` с пагинацией.

**Выход:** видимость «что нейродруг сделал и почему» для настройки промптов и порогов.

---

## Этап 5 — Онбординг, пресеты, первый монолог

- Галерея пресетов (JSON), персонализация в рамках допусков, lock ядра.
- Первое сообщение — генерация через orchestrator; **голос** (TTS) + дубликат в чате.

---

## Этап 6 — Память и семантика (углубление)

- **Сделано (первая итерация):** коллекция Qdrant при старте API; эмбеддинги OpenAI (`text-embedding-3-small`); индексация реплик пользователя и ассистента после голоса/текста и intro при создании; top-k retrieval в промпт LLM (фильтр по `neurofriend_id`). Код: `semantic_memory`, `embedding_openai`.
- **Дальше:** дублирование фактов в PostgreSQL при необходимости SoT; ежедневная консолидация (worker); importance/decay по SRS; заготовка `memory_consolidation.py`.

---

## Этап 7 — Инициатива, gap, push

- Gap detection, initiative score, quiet/DND, исходящие сообщения (сначала текст/TTS + уведомление).
- Очереди/воркеры на Redis.

---

## Этап 8 — Качество, наблюдаемость, смена голосового провайдера

- Метрики, Sentry, стоимость Whisper/TTS/LLM.
- Замена реализаций за интерфейсами `SpeechToText` / `TextToSpeech` без смены доменной модели.

---

## Порядок приоритетов (кратко)

1. Инфра + модели + **голосовой контур** (Этапы 1–2).  
2. **Чат-дубликат + 500/архив/10** (Этап 3).  
3. **Отладочный UI** отношений/событий (Этап 4).  
4. Онбординг и пресеты (Этап 5).  
5. Память/инициатива/полировка (Этапы 6–8).

При параллельной работе команды: после Этапа 2 можно вести Flutter UI (голос + чат) одновременно с Этапом 4 API.
