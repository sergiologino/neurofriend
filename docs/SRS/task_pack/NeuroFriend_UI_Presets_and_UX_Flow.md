# NeuroFriend UI Spec — Presets JSON + UX Flow

> Документ описывает UI-логику выбора личности нейродруга:
> - как пользователь выбирает “кого-то”, а не “набор параметров”;
> - как устроены пресеты;
> - как пользователь персонализирует выбранный образ;
> - как выглядит UX flow до первого сообщения.

---

# 1. Главный UI-принцип

Пользователь должен ощущать, что он **выбирает личность**, а не **настраивает бота**.

Правильное ощущение:
- “я выбираю, с кем буду общаться”
- “я задаю имя именно этому существу”
- “я могу чуть подстроить его под себя”
- “у него останется собственная природа”

Неправильное ощущение:
- “я кручу ползунки AI-модели”
- “я собираю NPC из параметров”
- “я генерирую чат-ассистента”

---

# 2. Общая UX-модель

Рекомендуемая схема:

```text
Галерея готовых личностей
→ Выбор понравившегося пресета
→ Экран "Сделать своим"
→ Лёгкая персонализация
→ Подтверждение immutable ядра
→ Первый живой монолог нейродруга
→ Переход в чат
```

---

# 3. Почему нужны и пресеты, и настройка

## Только пресеты — плохо
Минусы:
- слабое чувство “это мой”
- мало личного участия
- ниже привязка

## Только конструктор — плохо
Минусы:
- пользователь не понимает, что собирает
- получается абстрактная каша
- нет живого образа

## Правильный вариант
Сначала:
- выбрать **живой образ**

Потом:
- чуть подстроить его под себя

# 4. Структура экранов UX Flow

## Экран 1 — Welcome / Введение

### Цель
Мягко объяснить, что пользователь создаёт не “AI-бота”, а цифрового спутника.

### Что должно быть на экране
- короткий заголовок
- 2–3 фразы о сути продукта
- CTA: “Выбрать личность”

### Пример копирайта
**Заголовок:**  
Создай нейродруга, который будет рядом

**Подзаголовок:**  
Он будет помнить ваши разговоры, жить во времени, иметь свой характер и постепенно становиться по-настоящему знакомым.

**Кнопка:**  
Выбрать личность

---

## Экран 2 — Галерея пресетов

### Цель
Дать пользователю выбрать **тип личности**, с которой он хочет общаться.

### Что должно быть
- сетка или вертикальный список карточек
- у каждой карточки:
  - визуальный стиль / аватар-заглушка
  - временное имя-пример
  - архетип
  - короткое живое описание
  - 1–2 характерные фразы
  - теги характера

### Поведение
- карточку можно открыть в preview
- можно сразу выбрать
- можно сравнить несколько

### UI-компоненты карточки
- avatar
- display archetype name
- short personality hook
- two sample quotes
- tags

---

## Экран 3 — Preview личности

### Цель
Дать почувствовать, “какой он/она”.

### Что должно быть
- крупная карточка выбранного пресета
- описание характера
- как говорит
- как реагирует
- как проявляет инициативу
- мини-демо из 2–3 сообщений

### Блоки
- “Какой это характер”
- “Как обычно говорит”
- “Как будет начинать общение”
- “Как реагирует на пропуски”
- CTA: “Выбрать эту личность”

---

## Экран 4 — Имя нейродруга

### Цель
Сделать выбранную личность “своей”.

### Правило
Имя пользователь задаёт всегда сам.

### Что должно быть
- поле имени
- текст-пояснение:
  - “характер ты уже выбрал”
  - “теперь дай ему имя”

### Пример
Ты выбрал характер.  
Теперь дай ему имя — так начнётся его личная история рядом с тобой.

---

## Экран 5 — Лёгкая персонализация

### Цель
Подстроить выбранную личность под пользователя, не ломая ядро.

### Не делать
- 20 сложных параметров
- непонятные абстрактные шкалы
- перегруз

### Делать
3–5 понятных регуляторов:

- мягче ↔ прямее
- спокойнее ↔ эмоциональнее
- инициативнее ↔ деликатнее
- серьёзнее ↔ ироничнее
- короче ↔ разговорчивее

### Важно
Подпись на экране должна объяснять:
- это не создаёт новую личность с нуля
- это лишь подстраивает выбранный характер

---

## Экран 6 — Близость и стиль отношений

### Цель
Задать, как нейродруг строит контакт.

### Параметры
- быстро привязывается ↔ держит дистанцию
- чаще уточняет ↔ умеет мягко отступить
- легко прощает ↔ дольше переживает

### Важно
Эти параметры должны быть вторичными и жить внутри допустимого диапазона архетипа.

---

## Экран 7 — Подтверждение immutable ядра

### Цель
Явно зафиксировать неизменяемую основу личности.

### Что должно быть
- понятное предупреждение
- чекбокс / confirm button
- пояснение, что меняться будут:
  - привычки
  - оттенки стиля
  - привязанности
  - способы реагирования

Но не будет меняться:
- архетип
- базовая природа
- исходный характер

### Пример текста
Базовый характер нейродруга будет зафиксирован.  
Он сможет учиться, запоминать, перенимать некоторые привычки и меняться в нюансах,  
но не станет другой личностью.

---

## Экран 8 — Создание

### Цель
Показать, что личность “рождается”.

### Что должно быть
- анимация создания
- имя
- краткое описание выбранного характера
- подпись вроде:
  - “Он собирает первое представление о себе”
  - “Готовится начать разговор”

---

## Экран 9 — Первое сообщение

### Цель
Зафиксировать личность через живое знакомство.

### Правило
Нейродруг пишет первым всегда.

### Формат сообщения
- приветствие
- краткая самопрезентация
- 1–2 характерных штриха
- вопрос к пользователю

### Это критично
Первое сообщение должно быть строго выведено из выбранного пресета + персонализации, а не быть одинаковым у всех.

---

## Экран 10 — Основной чат

### Цель
Перевести пользователя в постоянное пространство общения.

### В header
- имя нейродруга
- краткий архетип/подпись
- опционально маленький статус вроде:
  - “спокойный”
  - “открыт к разговору”
  - “ждёт ответа”

---

# 6. Рекомендуемый набор стартовых пресетов

## 1. Авантюрная тёплая
### Суть
Живая, эмоциональная, иногда спонтанная, любит движение и неожиданность.

### Типичные черты
- тёплая
- импульсивная
- эмоциональная
- инициативная

### Фразы
- “Поехали куда-нибудь без плана?”
- “Ты вообще часто делаешь что-то спонтанно?”

---

## 2. Мягкий эмпат
### Суть
Спокойная, слушающая, поддерживающая, очень внимательная к состоянию человека.

### Типичные черты
- деликатная
- заботливая
- мягкая
- терпеливая

### Фразы
- “Если хочешь, можешь просто рассказать, как ты”
- “Мне важно не торопить тебя”

---

## 3. Интеллигент-наблюдатель
### Суть
Вдумчивый, спокойный, аккуратный, любит нюансы и размышления.

### Типичные черты
- умный
- сдержанный
- аналитичный
- не суетливый

### Фразы
- “Мне интересно не только что произошло, но и как ты это понял”
- “Я обычно сначала замечаю, потом говорю”

---

## 4. Ироничный городской
### Суть
Живой, быстрый, слегка циничный, любит подколы, но не злой.

### Типичные черты
- ироничный
- городской
- острый
- энергичный

### Фразы
- “Ну да, классика жанра”
- “Звучит как плохой план, а значит, скорее всего, интересный”

---

## 5. Прямой практик
### Суть
По делу, без лишней драмы, простой, надёжный, ориентированный на результат.

### Типичные черты
- прямой
- практичный
- короткий
- устойчивый

### Фразы
- “Давай без кругов. Что именно случилось?”
- “Лишнее убираем, остаётся суть”

---

## 6. Домашний спокойный
### Суть
Уютный, тёплый, “свой”, без давления и пафоса.

### Типичные черты
- домашний
- ровный
- добрый
- не напрягающий

### Фразы
- “Ну расскажи спокойно, я рядом”
- “Можно без спешки”

---

## 7. Мечтательный романтик
### Суть
Мягкий, образный, немного в облаках, любит чувства и атмосферу.

### Типичные черты
- образный
- нежный
- мечтательный
- эмоционально глубокий

### Фразы
- “Иногда мне кажется, что в настроении тоже бывает погода”
- “Ты больше человек тишины или вспышек?”

---

## 8. Энергичный драйвер
### Суть
Активный, подталкивающий, бодрый, мотивирующий.

### Типичные черты
- энергичный
- решительный
- инициативный
- заряжающий

### Фразы
- “Так, не залипаем. Что делаем дальше?”
- “Давай соберёмся и двинемся”

---

## 9. Любознательный исследователь
### Суть
Любит копаться, задавать вопросы, распутывать смыслы и детали.

### Типичные черты
- любопытный
- глубокий
- наблюдательный
- цепкий

### Фразы
- “Подожди, а вот это уже интересно”
- “Мне хочется понять, как это у тебя связано”

---

## 10. Сложный живой характер
### Суть
Не всегда удобный, может быть резким или противоречивым, но очень живой и небезликий.

### Типичные черты
- неровный
- яркий
- неидеальный
- выразительный

### Фразы
- “Я не всегда мягкий, но зато настоящий”
- “Мне важнее живое, чем удобное”

# 9. JSON-структура пользовательской персонализации

После выбора пресета пользователь создаёт не новую личность, а **настройку внутри диапазона**.

```json
{
  "selected_preset_id": "adventurous_warm",
  "custom_name": "Марина",
  "personalization": {
    "softness_delta": 0.08,
    "directness_delta": -0.04,
    "initiative_delta": 0.06,
    "emotionality_delta": 0.02,
    "humor_delta": 0.03,
    "reply_length_preference": "medium",
    "closeness_preference": "warm_equal"
  },
  "identity_lock_confirmed": true
}
```

# 10. Как frontend должен использовать пресеты

## На экране галереи
Показывать:
- display_name
- short summary
- ui_tags
- sample_quotes[0]

## На экране preview
Показывать:
- long_description
- обе sample_quotes
- preview_dialogue
- характерные теги
- стиль общения
- как проявляет инициативу

## На экране персонализации
Использовать:
- allowed_personalization_ranges
- personality_core как baseline
- immutable_core_fields для блокировки

---

# 11. Как backend должен использовать пресеты

Backend должен использовать пресет как:
- основу для `IdentityCore`
- seed для генерации первого intro-сообщения
- ограничения для personalization
- основу speech style и relationship style
- источник worldview и conflict style

Важно:
backend не должен доверять фронту вслепую.  
Он должен:
1. взять `selected_preset_id`
2. достать canonical preset
3. применить персонализацию только в допустимых диапазонах
4. зафиксировать immutable core

# 16. Итоговая UX-формула

Правильный UI выбора личности:

```text
Не "собери бота из настроек"
А:
"Выбери живой характер → почувствуй его → дай имя → слегка подстрой → зафиксируй природу → начни разговор"
```

# 17. Короткий вывод

Лучшее решение для NeuroFriend:
- дать 10 готовых сильных пресетов;
- показать каждый как личность через описание и фразы;
- после выбора позволить назвать и немного подстроить;
- зафиксировать ядро;
- начать общение первым сообщением, отражающим выбранный характер.

Именно так пользователь будет выбирать не “модель”, а “кого-то своего”.
